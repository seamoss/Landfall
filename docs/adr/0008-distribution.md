# 0008. Ship as a Developer ID-signed, notarized app bundle via GitHub releases

- **Status:** Accepted
- **Date:** 2026-10-12 (icon and release automation added 2026-10-13)

## Context
A bare executable gets new macOS folder-permission prompts on every rebuild, can't use Notification Center or login items properly, and is blocked by Gatekeeper on other Macs.

## Decision
- Package `Landfall.app` (bundle id `com.noisebeard.Landfall`, `LSUIElement`), universal (arm64 + x86_64), minimum macOS 14.
- Sign with the Developer ID Application certificate (team 4J2T5H73JM) using the hardened runtime and only two entitlements: Apple Events (Terminal for "Run in Terminal…") and Calendars. No sandbox: the app's job is moving files between user folders.
- Notarize and staple the app and DMG with a `notarytool` keychain profile (`landfall-notary`).
- The app icon is an Icon Composer document (`Resources/Landfall.icon`) generated by `scripts/make-icon.swift` and compiled with `actool`: Liquid Glass on macOS 26, a flat icon for earlier systems.
- Start at login with `SMAppService.mainApp`; the earlier LaunchAgent is retired by the installer.
- `scripts/release.sh <version>` bumps `VERSION`, runs tests, packages, refuses anything not notarized, commits, tags, pushes and publishes a GitHub release with the DMG and its SHA-256, using the CHANGELOG's Unreleased section as notes.

## Consequences
- Folder permissions persist across updates because the signing identity is stable.
- Releases depend on the signing certificate and notary profile on the release machine.
- In-app updates: see [0009](0009-sparkle-updates.md).
